会議レコーダー 概要 仕様 アーキテクチャ 意思決定記録

仕様

アプリが何をするか、何を保存するか、利用者が何を操作できるかをまとめます。 なぜその形になったかは意思決定記録を参照してください。

動作要件

項目要件理由
macOS 14.2 以上 Core Audio Process Tap API の導入バージョン
CPU Apple Silicon whisper / LLM の Metal 高速化、配布ビルドが arm64 のみ
メモリ 16GB 以上 要約モデル（q4 で約 5GB）を読み込むため
空き容量 約 10GB モデル 5.7GB ＋ 録音データ
ネットワーク 初回のモデル取得時のみ 以降は完全にオフラインで動作する

権限

初回録音時に 2 つの許可を求めます。どちらも録音に必須です。

権限Info.plist キー用途
オーディオ録音 NSAudioCaptureUsageDescription 会議相手の音声（システム出力）の取得
マイク NSMicrophoneUsageDescription 自分の発言の録音
内蔵マイクが無い機種があります。 Mac mini や Mac Studio には内蔵マイクがありません。マイクが 1 つも接続されていない場合、 そのアプリは「システム設定 > プライバシーとセキュリティ > マイク」に現れません （存在しないデバイスへの権限は要求できないため）。この状態でも 相手の音声のみで録音は続行されます。自分の発言も残したい場合は 外付けマイクを接続してください。
署名が必須です。 NSAudioCaptureUsageDescription による権限は署名済みバイナリでしか有効になりません。 無署名で配布するとシステム音声が取得できず、しかも原因が分かりにくい形で失敗します。 証明書が用意できない場合でも ad-hoc 署名は必ず行います。

録音

  • デスクトップ音声（相手）とマイク（自分）を別トラックで同時録音します。
  • 録音・停止はどの画面でも画面下部のバーから操作できます。
  • ウィンドウを閉じていてもメニューバー（トレイ）から開始・停止できます。
  • 録音中は経過時間とマイク入力レベルを表示します。
  • 既定は 16kHz モノラル。whisper が 16kHz を前提としており、会議音声には十分なためです。 設定で 8000〜48000Hz に変更できます。
  • データはメモリに溜めず逐次ディスクへ書き出します。クラッシュしても そこまでの音声は残ります。

停止後の処理

停止すると 5 つのステップが順に実行されます。処理中も UI は操作でき、進捗が一覧に反映されます。

#ステップ内容依存
1ミックス 2 トラックを時刻整列し、クリッピング保護つきで 1 本の WAV に合成 —
2文字起こし whisper-cli を各トラックに個別実行し、話者 ID を付与してマージ —
3話者識別 相手トラックをクラスタリングし「参加者A / 参加者B …」に細分化（任意） 2
4要約 文字起こしから日本語の議事録を生成 2
5エンコード ミックス済み WAV を AAC へ変換し、中間ファイルを削除 1
失敗は依存するステップだけを止めます。 要約に失敗しても音声とエンコードは完了し、最も価値の高い成果物が守られます。 失敗したステップは詳細画面から個別に再実行できます。

話者識別

2 段階で構成しています。

段階方法精度有効化
自分 / 参加者 トラックの由来で決定（推論なし） 常に正しい 常時
参加者A / B / C … sherpa-onnx によるクラスタリング 環境依存 設定＋モデル取得時

話者名は詳細画面でクリックして変更できます。話者数の上限を超えたクラスタは、 発話時間の合計が短いものから捨てられ、汎用の「参加者」ラベルに戻ります。

保存されるファイル

保存先は初期設定で選びます。1 回の録音が 1 ディレクトリにまとまります。

<保存先>/
├── index.json                        一覧用のキャッシュ
└── 2026-09-06_1430_チーム定例/
    ├── meta.json                     この録音の情報（一覧はここから再構築できる）
    ├── audio.m4a                     AAC-LC 32kbps mono（1 時間あたり約 14MB）
    ├── transcript.json               話者・時刻つき（機械可読）
    ├── transcript.md                 コピペ用
    ├── summary.md                    要約
    └── note.md                       自分のメモ
置き場所内容方針
利用者が選んだ保存先 音声・文字起こし・要約・メモ 他のツールでも読める形式（m4a / Markdown / JSON）のみを置く
~/Library/Application Support/…/work/ 録音中の WAV、トラック情報 エンコード完了後に削除。保存先を汚さない
~/Library/Application Support/…/models/ ダウンロードしたモデル 再取得できるキャッシュなので保存先とは分ける

index.json はあくまで一覧表示を速くするためのキャッシュです。正は各ディレクトリの meta.json で、index.json を失っても壊れても一覧は再構築されます。 利用者がディレクトリを整理・移動しても録音が消えません。書き込みは一時ファイル経由の置換で行うため、 中断しても壊れたファイルが残りません。

モデル

初回起動時の画面からアプリ内でダウンロードできます。事前準備は不要です。

用途モデルサイズ必須
文字起こし whisper large-v3-turbo（q5_0） 574MB はい
要約 Gemma 4 E4B（QAT q4_0） 5.2GB はい
話者分割 pyannote segmentation 3.0 7MB いいえ
話者埋め込み 3D-Speaker CAM++ 28MB いいえ
  • 中断でき、次回は途中から再開します（Range 要求）。
  • 必須モデルは sha256 を検証します。壊れていれば保存せず破棄します。
  • 完成するまで最終パスに置かないため、中断で壊れたモデルを掴むことがありません。
  • 取得したパスは自動的に設定へ書き込まれます。利用者がパスを入力する必要はありません。

モデルが無くても録音は始められます。先に会議を録っておき、後から詳細画面で 文字起こしと要約だけを実行できます。

対応していないこと

  • リアルタイム字幕。録音中は推論を行わず、停止後にまとめて処理します。→ ADR-009
  • Intel Mac。配布ビルドは arm64 のみです。
  • Windows / Linux。Core Audio Process Tap と afconvert が macOS 固有です。
  • クラウドのモデル。ポートは分離してあるため追加は可能ですが、現状の実装はローカルのみです。
  • 既定以外の出力デバイス。audiotee は既定の出力デバイスのみを取得します。
  • 自動更新。Release からの手動ダウンロードのみです。
